# Phase 4: UI and Micro-interactions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the spec's Phase 4: a calmer page, modern browser features as progressive enhancement, and the micro-interactions (tooltips, transitions, change highlights, copy feedback, shortcuts, undo, mobile bar, real signup form, self-hosted fonts).

**Architecture:** Every behaviour that can be decided without a DOM lives in a small pure module with a `node --test` file: `tooltip.js` (fallback placement), `motion.js` (view transition gate), `diff.js` (sources added and removed), `shortcuts.js` (key to action), `store.js` (the store, extracted from `ui.js`, with reset and undo), `signup.js` (email validation message).
Markup changes in `index.php` and `lib/icons.php` are pinned by the PHP runner through `render_index()`.
Everything visual is verified by Playwright scripts in the scratchpad, in Chromium, WebKit and Firefox, light and dark, 1280, 390 and 320 px.

**Tech Stack:** PHP 8.5, native ES modules, CSS (`light-dark()`, `@starting-style`, `interpolate-size`, `::details-content`, anchor positioning), Popover API, View Transitions API, `node --test`, plain PHP test runner, Playwright. No npm or composer in the project.

**Spec:** `docs/superpowers/specs/2026-11-04-generator-overhaul-design.md` (sections "Phase 4 - UI and micro-interactions" and "Browser support").

## Global Constraints

- Zero build tooling. Modules stay flat in `assets/js/` (the import map only globs `assets/js/*.js`).
- No em dash anywhere. No commented-out code, no silent catch blocks. Conventional commits, no agent co-author line. `./scripts/check.sh` exits 0 before every commit.
- Our own CSP stays strict: no inline handlers, no `style=""` (positions and widths are set through the CSSOM), no `'unsafe-inline'`.
- "Every Phase 4 feature is progressive enhancement and must degrade to a working, readable page."
- "Source reasons are never reachable only through a tooltip." The Header tab's "Why each source" list stays.
- "Tooltips use the Popover API, with anchor positioning where supported and a simple fixed placement below the trigger otherwise."
- Motion is skipped under `prefers-reduced-motion: reduce` (view transitions, `@starting-style` entries, highlight flashes, FAQ height animation).
- Already shipped in Phases 2-3, keep as is: presets in the config header, `role="switch"` toggles, ARIA tablist with arrow keys, section header buttons with `aria-expanded`.
- Branch `phase-4-ui`, cut from `phase-3-tools`. The PR targets `phase-3-tools` until #5 merges.

## Review Focus

1. A shortcut key typed into a text field, the search box, a date input or an open dialog: it types normally, no tab switch or copy. Pinned in Task 9.
2. Reset, then a further change before Undo: the undo is dropped (the toast closes), so Undo never throws away newer work. Pinned in Task 10.
3. A browser without anchor positioning, View Transitions or `interpolate-size` (Firefox today): tooltips sit below the trigger inside the viewport, tabs switch instantly, FAQ opens without animation. Pinned in Tasks 5, 6 and the Task 13 Firefox pass.
4. A tooltip trigger at the right or bottom edge of a 320 px viewport: the tooltip stays fully on screen. Pinned in Task 5.
5. A signup with an invalid email or a server error: a visible text message tied to the field with `aria-describedby`, not only a red border, and the button is usable again. Pinned in Task 3.
